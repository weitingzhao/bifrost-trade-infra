## 1. 主要矛盾

多种 Agent 工具（Claude Code 线程、Cursor、Grok Bot，以后可能有 OpenAI Codex），分布在多台主机（Mac Pro、Mac mini .50 / .52），共用四样稀缺的东西：**代码、发布通道（一个窗口、一个 PROD）、台账、Owner 的注意力（批准与签收）**。

今天的协调手段全都依赖 Mac Pro 开着、而且对方线程还活着：

| 手段 | 局限 |
|---|---|
| Claude 会话之间的 `SendMessage` | 只在本机、只对活着的 Claude 会话有效；Grok、Cursor 收不到；线程结束消息就发不过去 |
| 发布窗口 `~/.bifrost-release/window.json`（ConfigMap `cicd/bifrost-release-window` 只是镜像） | 权威在 Mac Pro 的文件上；是锁不是队列，谁拿到谁发，其余干等 |
| Grok Bot（Der）写给 Claude 的提示词 | 只有 Der 发起的轮次能看到 |
| Owner 在线程之间转话 | Owner 成了消息总线 |

## 3. 核心思路：靠共享状态协调，不靠互相发消息

所有 Agent——不论什么工具、在哪台主机——只读写**同一个 24 小时在线的地方的几条事实**，彼此不需要知道对方是谁、是否还活着。

**这个地方是 PROD platform-api**（Owner 已定）。理由：
- 已经 24 小时在线；
- 已有鉴权、审批、审计和备份（platform-state 在集群状态备份里）；
- ADR §4 已定它是唯一的运行控制面；
- 这些能力不涉及 Trade 业务，通过平台/业务解耦的克隆测试。

**这不是调度器。** ADR §1「Ops Platform 不再托管或派发 Agent」不变：派活的仍然是 Grok Bot 或 Owner，平台只提供事实和护栏。

### 四样东西（护栏，不是新系统）

| | 内容 | 解决 |
|---|---|---|
| ⓪ 身份 | 每个「工具 × 主机」一个令牌（如 `cursor@pro`、`grok@mini50`、`codex@…`、`claude@pro`），最高只到 operator，不给 admin。写操作记录调用方；提交带 `Agent:` 尾注（有钩子的工具由钩子补，没有钩子的由 CI 标出「无归属」） | 1e277a5 这类提交没有归属 |
| ① 认领 | 开工前认领一个工作项（`TD-n` / `LANE-…` / `W-n`），带心跳续约，过期自动释放。所有人都能看到「X 从几点起在做」。**先只做提示，不拦截**（Owner 已定） | 重复劳动 |
| ② 发布队列 | 发布窗口的权威从 Mac Pro 的文件迁进 platform，并且变成**队列**：任何人提单 → 批准（Owner 点，或命中已签的发布策略）→ 由集群内的执行器按顺序执行。批准时钉住提交号；执行前 main 变了就不执行，推送通知请 Owner 重批；排队超过 24 小时自动过期并通知。窗口被占时排队等待，不作废（TD-267 并入）。**这是唯一强制的一条**，因为它是发版的唯一通道 | 线程互相等、Owner 不知道什么时候点、单子作废 |
| ③ 待办箱 | 交接和「需要 Owner」的事项发给**角色或工作项**（批准 / 签收 / 验收报告），不发给某个具体线程。发给 Owner 的推送到手机（复用审批通知的 ntfy 链路） | 线程结束后消息丢失；Owner 在中间转话 |

**明确不做**：平台里的派发与调度；汇总各主机的对话记录；Agent 之间的聊天总线。

## 4. 各工具怎么接进来

- **统一接口用 MCP**：Claude Code、Cursor、Codex 都支持 MCP；Grok Bot 不支持的话直接打 HTTP。四样东西做成现有 `bifrost-platform` MCP server 里的几个工具（大致是 `whoami`、`claim_work` / `release_claim`、`request_release`、`post_handover` / `list_inbox`）。
- **同一段约定写进每个工具的规则文件**：Claude 是 `CLAUDE.md`，Cursor 是 `.cursor` 规则，Codex 是 `AGENTS.md`，Grok 是它的提示词。约定只有三句：先认领再开工；发版只提单，不占窗口；交接写进待办箱。
- **能用钩子的就用钩子**：Claude 的 SessionStart / Stop、Cursor 的 `hooks.json`，用来自动续约和释放认领。

## 5. 机器分工

- **Mac Pro**：Owner 的驾驶舱和交互线程。它睡了，协调照常；只是跑在它上面的线程会停。
- **Mac mini 的 Agent 虚拟机**（ADR §3 的 A 方案已经预留）：放 Grok Bot 和 headless 的 claude / cursor / codex。每个 Agent 有自己的 git 克隆和令牌，因此不再共用 Mac Pro 上的单一工作树，共享工作树的暂存事故随之消失。
- **看状态的地方**：PROD Console 的 ④（待你批 / 签）、⑤（发布与队列）、⑦（进度：工作项、认领、提交、到了哪个环境）。这三页 ADR §6 已有，不另开页面。
