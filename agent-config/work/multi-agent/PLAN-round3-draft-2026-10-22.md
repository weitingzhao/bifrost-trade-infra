## 二、第 3 轮要 Owner 定的事

每题都有推荐，回「D1 A、D2 A……」即可；没回的题按推荐走、事后审计（Owner 10-11 的规矩），**架构题（D2）除外，必须等他回**。

### D1　第 3 轮的主线

背景：Owner 10-19 定「当前阶段完成后，先做 Screening 档案与授权最小版，再做最小业务闭环（提议或反馈 → 评估 → 接单 → 交付 → 太太试用 → 记录结果）；其他机制先不扩」。10-21 又定了两项进第 3 轮：Agent 资格流水线（薄版）、发版提速（结构）。

- **A（推荐）**：**Screening 最小业务闭环是主线**；资格流水线薄版、发版提速①②当配套，并行做，只做主线用得上的部分。理由：第 2 轮的目的就是「用这套协作做真实工作」；业务优先（Owner 09-26 定的规矩）；两项机制都直接减少主线里的等待。
- B：先做两项机制，再做 Screening。
- C：第 3 轮只做机制，Screening 再往后。

### D2　资格流水线（薄版）的考题答案放在哪（架构题）

背景：现在每次换模型或改题都要 Owner 在终端输口令放题集（考题要点不能进 Agent 能检出的仓库）。薄版要求「平台自动发卷不用我输口令」。

- **A（推荐）**：题集和要点放在集群 Secret 里，只有控制器读得到；Owner 每换一套题集签一次（一条命令），之后换模型、换岗位时平台自动发卷、自动判分、结果进考试记录。新增：考试运行记录（一张表或复用事件流，交给实现线定、复核把关）。
- B：放平台库里的加密列，平台自己解密。
- C：维持现状（Owner 每次输口令）。

### D3　发版提速先做哪几条

- **A（推荐）**：先做 ①「PROD 直接部署 STG 已核对过的镜像摘要，不再从源码重建」（省约 4 分钟，也更安全；就是 TD-335）和 ②「CI 在分支上先跑，绿了才合 main」。③「无人值守的小改动 PROD 发布」要先定发布策略和签名，放到第 3 轮后段。
- B：①②③ 一起做。
- C：只做 ①。
