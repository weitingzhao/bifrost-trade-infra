# 实践中卡住的地方（卡点台账）

Owner 2026-10-10：「我们在做这个项目的过程本身就是在实践多 Agent 协作架构的某种模式。现在能被卡住的，将来也一定会被卡住，所以需要吸取教训。」

这份文件登记做 W-31 的过程中每一次卡住、空等或差点出错：卡在哪、为什么、当时怎么过的、系统建成后靠什么机制不再卡、落在哪个工作项。规则：

- 统筹的线程每次遇到卡点就加一行，当天加，不靠事后回忆。
- 每一行要么对应一条运行时要求和一条测试，要么写明「接受，不处理」和理由。
- 阶段门槛的验收（ADR §12.10）要把这里的场景跑一遍；只在本文件里写了、没有机制兜住的，不算解决。
- 临时的手工做法（今天怎么过的）不算机制。
