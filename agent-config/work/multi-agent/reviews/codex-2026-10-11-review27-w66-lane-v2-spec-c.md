- **P2 — B11 不一定保持 `verdict_pending` 或补落同一判词。** §4 L100 要求按步骤顺序检查证据；L107 的早期无效证据会挡住后续步骤的人工关闭。具体序列：implement、verify 已成功记账 → review 未记账且驱动死亡 → `resolve review --kind failed` 写入 resolution 后崩溃 → implement 的 manifest 丢失。此时重算先得到 implement 的 `unknown`，到不了 review 的关闭结果；与 §6 L172 和 T54 L248 承诺的直接补落同一判词不符。不会放行，但实施者必须猜恢复优先级。应明确关闭后终局结果如何固定，或明确允许重新阻塞；补一个 B11 后早期证据丢失的测试。
