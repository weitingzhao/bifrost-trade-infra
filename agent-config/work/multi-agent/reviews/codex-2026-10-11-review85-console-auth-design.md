P1 · §2、5、10（甲）：路径拦截缺少规范化要求。最便宜的绕过是在角色仍为 `checking`、存储中已有有效 admin token 时，经 `request` POST `/api/v1/./approvals/{id}/approve`；原始路径不匹配所述决策路径，浏览器却会去掉 `/./`，请求到达真实路由，跳过当前纪元的身份确认。类型、ESLint、现有矩阵均可保持绿灯；服务端仍要求 admin token，此处是客户端闸门绕过。
最小修改：发送与判定使用同一规范化 URL；明确拒绝点段、编码歧义、反斜杠等非规范路径。§10 加入角色未确认时这些路径的拒发测试。

P1 · §4、9、10、13（乙）：`keepRefusalBody` 仍将任意服务端文字变成 Error.message，进入页面和查询错误缓存。base64、百分号编码、拆分字段、截断及大小写变化可通过原样检查；JSON 转义在解析后通常会被抓到，但不能使整体检查可靠。300 字符截断也不是保密边界。
最小修改：片 1 就删除所有拒绝正文透传，只返回本地固定文字和封闭错误码；操作详情按明确字段契约保留。成功数据也须规定字段投影、转换后检查，并补编码及拆分测试；删除“乙类在结构上关闭”的过度保证。

P2 · §5、7、10：路由核对只指定 `approvals/handler.go` 的 admin 组，漏掉 `questions/handler.go:33–34`，也未明确新增路由必须失败。新增问题决策路由再经 `request` 调用，可避开所述路由测试。
最小修改：核对两个 Mount 的完整决策集合，要求集合相等；覆盖挂载前缀及别名，并加入“新增服务端决策路由而未更新模块时测试失败”的阳性对照。

P2 · §4、5、13：源码不支持“所有 4xx 都发生在改状态之前”：审批和问题处理会先 sweep 并持久化过期状态，再返回 409。相同问题答案重放返回 200、`replayed:true`（`questions/transition.go:31–34`），不同答案才返回 409。
最小修改：将 `refused` 定义为“本次提交的决定未被接受”，不代表记录未变或其他通道没执行；补相同答案重放、过期、其他通道已决定的契约测试。

P2 · §5、10：恢复读取未明确排除缓存和发送前已开始的 GET。旧 `pending/open` 响应可在 POST 后到达，错误地恢复控件；即使新 GET 仍显示 pending，也不证明原请求之后不会生效。
最小修改：恢复必须使用发送结束后启动、绑定当前纪元的独立 GET，绕过查询缓存并用 `cache:'no-store'`；取消或丢弃早先读取，保留终态防倒退。补旧缓存、迟到 GET、原 POST 晚完成测试，并规定决定请求的有限超时。

P2 · §2、3、8、10：正常可读存储下，每入口对账能处理漏事件、同页直接写入及浏览器清空；私密窗口则是独立登录。未定义存储由可用变为不可读时如何处理，也未覆盖 HMR 留下的旧模块、监听器和计时器；Strict Mode 与两个 provider 本身不应重复初始化模块。
最小修改：区分“键不存在”和“读取失败”，明确内存模式的进入及恢复规则；HMR 采用清理或整页重载。补同页 clear、存储读写异常、两个 provider 和热更新测试。

P2 · §6、13：“服务端拒绝后徽章变 NOT ACCEPTED”不一定成立：若 capabilities 重读网络失败，§3 会保留 ADMIN；viewer 行还固定写 OPERATOR。
最小修改：让固定文案按实际角色生成，明确角色暂无法重确认时的显示。现有 UNKNOWN 和结果未知都有恢复入口；手机验收须检查入口、邻近提示和可点击状态，`ready` 应明确仅表示此浏览器可提交决定。

P3 · §7、11：已核实 `pipeline-ci-platform.yaml` 的 Console 步骤只有 `npx tsc --noEmit`，没有 lint 或 vitest。当前不存在已实施的新模块保证；实施后 tsc 也只能约束类型，不能证明路径拦截、存储唯一入口或无泄漏。
最小修改：保留门禁前置条件，并要求实际 CI 对片 1 SHA 跑三项且失败阻断。片 1 可分模块与调用迁移两批审阅、整体交付；两轮额度从完整候选通过门禁后计算。

P3 · §12、13：passkey 和登录保留时长确属 Owner 决策，但 passkey 本身不解决共用设备上的持续会话；闲置超时也不等于每个新标签页都重新登录。
最小修改：改为“短期会话、锁定及敏感操作重新认证共同降低风险”；保留现状作为明确取舍，不把设备风险已解决写成保证。
