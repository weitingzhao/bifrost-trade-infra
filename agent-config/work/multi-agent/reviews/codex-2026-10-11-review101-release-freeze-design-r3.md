- **P1 — §3.2，字符串语义未闭合。[document]** 合规单项 LIST 的项内加入 `"x":{"\ud800":0,"\ud801":1}`：字节合法 UTF-8，RFC 8259 语法允许这些转义，但未规定其解码语义。Python 实测保留两个不同键；[Go 标准库](/opt/homebrew/opt/go/libexec/src/encoding/json/decode.go:98) 将二者替换为 U+FFFD。逐层检查重复键时，可分别得到 `frozen` 和 `unreadable`。最小修改：所有字符串必须解码为 Unicode scalar 序列，拒绝未配对 surrogate；重复键按转义解析后的序列比较，不做 Unicode normalization。
- **P2 — §3.2，压缩契约仍缺可执行定义。[document]** “压缩必须解开”没有限定 Content-Encoding、多个编码及 gzip 多成员、尾随数据的处理。最小修改：明确允许的编码及完整解码规则，其余为 `encoding`；关闭 Go 自动压缩协商和透明解压，再由两侧统一计数、解码。否则额外 Accept-Encoding 和线上大小上限容易失守。
- **P2 — §3.2，“全函数”承诺超出进程内可恢复范围。[document]** Python 的 BaseException 与 Exception 不同；Go 当前 goroutine 的 recover 捕获不了 HTTP 客户端其他 goroutine 的 panic，运行时致命错误也不能统一返回判定。最小修改：限定可恢复故障和注入边界；进程终止由调用方按失败关闭处理，禁止把终止等同于返回 `unreadable`。
- **P2 — §3.2、§8，生成器没有独立判据和预算。[slice 1 acceptance]** 两侧一致不能排除共同错误。最小修改：要求独立 oracle，固定种子和样本上限，覆盖每个位置、边界及多故障组合；分别记录生成器、穷尽模型和整包耗时，默认整包实测低于 40 秒。
- **P2 — §3.2，HTTP 中间响应未明确。[document]** Go 跳过非终结 1xx，Python 标准库默认只跳过 100；“状态恰好 200”需说明指最终响应。最小修改：明确中间响应、101 和 HTTP/2 push 的处理，并加入传输向量。没有证据表明健康 apiserver 会因此拒绝，故不列 P1。
- **P3 — §6，约 27 秒只是估算。[document]** 总耗时含固定成本，不能直接按序列条数线性缩放。最小修改：改为待实测目标，保留报告必须提供实测时间的要求。
