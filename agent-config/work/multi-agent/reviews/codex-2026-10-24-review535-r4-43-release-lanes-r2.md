**R1 — 接管改了记录里的代次，没有隔离已经通过车道任务的旧执行者（A2，优先级高）**

位置：`D:135–155,342`；验收 `D:482,497`。

这不是推测某个未写出的脚本会出错：现有钉摘要步骤在 `T/task-argocd-pin-sync-platform.yaml:220–228` 直接发 patch，没有操作代次；当前准入 `I/k8s/platform-rbac/40-admission.yaml:252–272` 只约束身份、应用和两个摘要的形状，没有比当前操作/代次。只加第二稿所列的开头车道任务，暂停反例仍成立。`W56:117,121,139,141` 原本要求副作用边界拒绝旧代次，并明确演练旧执行者醒来。

此外，`D:110` 保存 spec 哈希，`D:146–152` 却只列名字、参数和 revision；`D:116` 只有 run_name 没有 UID。确定名字能处理第一次 Create 响应丢失，但不是对象生涯身份，也不是 Pipeline/Task 规格验证。应将这些绑定写进同一验证契约，避免实现照检查列表漏掉它们。

交 Owner 的选项：

**R3 — M1 单个权威操作不等于单个实际 run，派生镜像仍有新的过渡间隙（A5）**

**R4 — seq 解开原来的等待环，但不能兑现无饥饿（A7，第二稿新洞）**
