- **P1 — 人工补记不能成为改判入口。** “结果未知”只能描述某个尚未完成记账的步骤，不能覆盖轮次裁决。人工只能追加：① 有证据的实际退出码及对应产物；② 已失败或已取消；③ 仍无法确认。必须记录操作者、原因、证据和 attempt 身份；不得直接填写 `passed`、覆盖已知非零退出码、把已记录的 `fix first` 改成通过，或重新开放已复核轮次。证据无法证明成功时，保持阻塞或关闭为未成功，重新执行只能进入受预算约束的下一轮。

- **P1 — 纯函数还缺完整放行契约。** 必须同时要求本轮所有必需步骤退出码为零、verify stdout 最后非空行为精确的成功标记、review 首尾符合完整报告协议且判词明确允许通过，以及全部内容快照有效并一致。stdout 与 stderr 分开保存；缺字段、未知退出码、无效判词、截断报告或 Git 查询失败均不得通过。必须明确失败优先级：成功文本不能压过执行失败。有效 verify FAIL 应进入允许下一轮修复的状态，避免 review20 的状态死路。

- **P1 — 新目录本身不能证明产物归属和完整性。** 启动前持久化唯一的 lane／round／step／attempt ID、步骤顺序、argv、cwd、任务书与配置摘要、仓库清单及预检查快照；所有产物引用必须绑定这些身份。每次独占创建目录和输出文件，禁止复用共享 `verify.txt`、追加旧日志或搜索“最近一份报告”。退出后关闭输出、取得后检查快照，记录实际 wait 退出码，并对完整产物记录长度和摘要；最后原子发布完成清单，再允许裁决读取。持久化需考虑 fsync；半写清单、缺失文件、身份或摘要不符都视为未知／无效。摘要用于发现错配与后续变动；同 Unix 用户可伪造全部记录的边界仍按题设接受。

- **P1 — 四次 HEAD＋clean 仍不足以保证内容一致。** 显式 `--untracked-files=all` 关闭了 review20 的配置漏洞，但不能覆盖被忽略的构建输入、`assume-unchanged`／`skip-worktree` 隐藏的修改、被配置忽略的子模块变化，以及检查期间“改了又改回”的情况。优先对固定提交建立独立验证快照；对子模块递归固定提交并检查实际内容，拒绝隐藏索引标记，忽略文件中的必要输入应固定并记录摘要或从受控材料重建。工具链、依赖和必要配置也要绑定证据，不能把所有 ignored 文件笼统视为无关。

- **P1 — 通过必须绑定提交集合，合并还需要独立闸门。** 各仓库 HEAD 必须在四点完全相同；amend 即使树相同也改变提交身份，应重新走轮次，不能默认为已复核。记录树 ID 有助于说明内容，但不能替代提交 ID。合并只消费裁决绑定的 SHA 集合，不能再读取可移动的分支 tip；执行时重新核对源提交、目标基线和裁决有效性。若合并产生不同的树，需验证实际合并结果。通过到合并之间的时间窗口不能靠历史 clean 快照封住。

- **P2 — 不管进程，仍要防止旧执行与下一轮重叠。** 驱动死亡不会自动终止孩子；启动成功但 PID 尚未落盘的窗口仍存在，正常退出也可能留下后台后代继续写文件。因此 `unknown`／`abandon` 不代表进程已停止；lane 锁释放也不代表工作目录可安全复用。在确认旧执行已结束或将新一轮隔离到新的执行目录前，禁止在同一可写目录推进。启动意图应先落盘，PID 尽早记录，并明确存在无法登记 PID 的启动歧义；程序不能再声称已回收。

- **P2 — 无人值守能力需要明确取舍。** 删除进程管理后，统筹失去终止失控实现者、挂起 reviewer 和自动释放资源的能力。“人来结束”可作为失败时暂停的方案，但不满足保证整夜持续推进的目标。如必须有停止能力，最小方案是交给独立执行器／宿主任务边界处理超时和取消；lane 只接收该 attempt 的取消或失败事实。停止不能改裁决、重开步骤、返还预算或自动重跑，也不能凭磁盘旧 PID／PGID 发信号。若暂不引入执行器，就应明确夜跑遇此情况停下等待人工。

- **P2 — 预算和待处理队列仍需程序持有。** 所有进入下一轮的路径统一检查预算；失败、取消和未知不能通过另建 attempt 免费重跑。统筹延期最多一次，追加 who／why／when 和新上限；后续仅 Owner 终端入口，不能只靠 `--by Owner` 字符串。按题设，同用户冒充不构成可消除的安全边界。队列必须显示未知、超预算、失败及已 abandon 但未确认结束的执行；看板由事件生成，不能继续依赖模型记着去看。
