**A1 [P1] — 递归删除核对的是“现在打开的子目录”，不是“复查通过的子目录”。**

位置：[disk_guard_apply.py:126](/Users/vision-mac-trader/agent-work/codex-review-544/snapshot/scripts/agent-host/disk_guard_apply.py:126)、[disk_guard_apply.py:43](/Users/vision-mac-trader/agent-work/codex-review-544/snapshot/scripts/agent-host/disk_guard_apply.py:43)，以及 [disk_guard_layout.py:48](/Users/vision-mac-trader/agent-work/codex-review-544/snapshot/scripts/agent-host/disk_guard_layout.py:48)。

第二次 `validate()` 返回的 Walker 只保存根身份和汇总，没有保留整树各子项的身份。随后还要执行 Git 子进程；最终 `_empty()` 重新 `listdir/stat`，把当时看到的所有目录递归清空、其他项直接 `unlink`。第 54 行的身份比较只证明这次 `stat` 与这次 `open` 一致，不能证明该子目录曾通过布局检查。

具体场景：共享 Go build 根超过上限，改名后的根第二次校验通过；在后续 Git 检查期间，另一使用者把其中 `00` 换成含 `draft.go` 或 `.git` 的目录，或者直接向 `00` 增加 `draft.go`，随后关闭文件。根 inode 不变；`cap` 策略不要求结束时间；lsof 快照已在这批复查之前取得（`apply.py:177`）。`_empty()` 会接受新 `00` 的当前身份，连新材料一起删除。机器 `flock` 只约束清扫器，没有约束缓存使用者。现有钩子测试在第二次校验**之前**修改树，不能覆盖此处。

最小修法：让第二次校验产出完整的允许删除清单，包含子项身份及必要的变化信息；删除只处理该清单，每一级对照校验时的身份，发现新条目／替换／变化就停止，不能对重新枚举出的未知项执行通用递归删除。若仍承诺“变化时整根原样保留”，最终检查到删除结束还需要使用者参与的互斥；已开始删除后不能靠改名恢复已删文件。补“第二次校验后新增文件／替换子目录”的仓库测试。
