# Response to review 524 (round 1), the coordinator · 2026-10-23

All four findings are taken.

- **A1 — the issue page keeps the previous identity's words after a token change or sign-out.** The issue query is bound to the signed-in identity (its key carries the identity; it is not enabled without one); on any identity change the page drops what it shows at once, the old request is cancelled (the query passes the abort signal to fetch) and the cached private data of the old identity is removed, so a late response cannot fill it back. Tests with the real PlatformAuthProvider: admin→viewer, admin→trade-satellite, sign-out, and a delayed old response; after each, neither the DOM nor the query cache holds the old text. Use the reviewer's probe (`~/agent-work/codex-review-524/probes/cache.node.test.tsx`) as a starting point.
- **A2 — the Owner's Decline on a priority card does not decline.** Done without a schema change (0009 does not let the controller write issue_state_changed, and a new migration would need another PROD DDL): `close_issue(conclusion=declined)` by the crew accepts, for a person's issue, the Owner's decline evidence on the current B (priority `declined`, transcribed by the controller from a card answered on the Console channel, not the rule channel), in addition to the Owner himself and her own withdrawn answer. Nothing else lets a thread decline a person's issue. After the decline evidence the shown state says the crew is to close it as declined (waiting_on crew), and the crew's stdio tool makes that close easy (the existing close tool with the conclusion; no new free-text path). Real-database test from a person's issue: a real card answered Decline → evidence → crew close → `closed/declined`, open asks voided, the requester's get_updates shows the closed update; refused with a decline on an old B, with a rule-channel answer, and for a thread with no such evidence.
- **B1 — after an evidence-less settle the issue still says it waits for the Owner.** Derive `owner_deciding / waiting_on=owner` at read time only while the issue has an open Owner card (from the neutral card notes already recorded); otherwise show the state the evidence gives. Tests: the last card expires; an answer that does not count; two cards, one settled.
- **B2 — a future cursor can be recorded as served.** An input cursor beyond what the server has handed this client (its served position) is refused (400) and changes nothing; served advances only to positions the query actually returned (or the horizon it computed), never to the caller's input. HTTP / real-database counterexample: the max-int cursor refused, served and acked unchanged, later replies still delivered.
