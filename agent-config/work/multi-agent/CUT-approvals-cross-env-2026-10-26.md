## 2. 选项与推荐

| 选项 | 路径 | 优点 | 代价 / 风险 |
|---|---|---|---|
| A（推荐）目标平台拉取 | STG 专用执行身份向 PROD 领自己环境的已批准子步骤，执行后回报 | 只需目标向 PROD 出站；目标离线自然积压；可复用认领、租约、结果语义；PROD 不持目标 DB 写凭证 | 需新增环境绑定认领协议、目标执行账本与可靠回报；不是直接复用宽权限的现有 executor token |
| B PROD 推送 | PROD 将已批准执行封套推给目标平台，目标持久化接受并异步回报 | 派发延迟低，中央可主动追踪 | 每个目标需入站受限入口与验证，PROD 持每环境派发身份；断网、重复推送仍需同样的账本和对账 |
| C PROD 直连各 runtime DB | PROD 用各环境写身份直接执行 | 少一个远程协议 | 扩大中央权限、绕过环境隔离；不是本案推荐，也不能作为临时回退 |

推荐 A。Owner 的“审批只在 PROD”已定；A/B 的传输选择在实施前确认。此 CUT 不把推荐冒充新的架构批准。无论 A/B，审批与最终结果只有 PROD 一份权威记录；目标只有执行日志/回执，不复制一套可人工批准的审批状态机。

## 3. 请求和批准

1. 调用者只向 PROD 建单，写明 `target_env`、动作、规范化参数、理由、回滚/补救、版本前置条件、证据摘要。目标环境参数和路由环境必须一致，不能同时有两个冲突的 env。环境白名单在服务端，不能从 URL/Host 推导。
2. PROD 在建单时校验目录、风险等级、远程可执行白名单、目标能力版本及参数形状。若依赖目标当前状态，使用有期限的目标预检证据，记录观察时间；目标离线或证据过期显示阻塞，不冒充检查成功。原动作的 D10 等边界继续生效。
3. 规范化后生成 `params_hash`，覆盖动作、目标 env、参数、前置版本与动作契约版本；计划合单另算 `plan_hash`，包含步骤集合、顺序/依赖、每步哈希、失败策略与补救范围。改动任一签署字段都使旧决定失效，不能在已批单后偷偷加环境或扩大动作。
4. Owner 在 PROD Console 看见目标环境、具体影响、未做的检查、部分失败策略后决定。tier D 保留确认编号/摘要哈希与 Console-only 约束。授权不是一张任意 shell 执行通行证。
5. 新建跨环境单用全局 approval ID；展示编号 `#n` 只在 PROD 分配。旧 STG #2 与 PROD #2 不可按数字相连。问题/签收型任务也使用中央 ID；目标 runtime 读取中央决定的投影并留来源，不以规则回答冒充 Owner 签收。

## 4. 认领、执行、回报（A）

建议协议字段，具体路由/表名在实施片定：`approval_id`、`step_id`、`target_env`、`action`、`contract_version`、规范化参数及其哈希、`plan_hash`、决定版本、执行代次、认领租约/栅栏序号、`approved_at`、`claim_before`、`execute_before`、签发者及 `key_id`。整个封套由中央授权签名，不只签参数。

- 目标平台用自身专用身份领单。PROD 从认证身份确定 env，只发该环境的已批准、未过期且依赖满足的步骤；不相信请求体自报 env。原 PROD 平台执行循环不得抢走 remote 步骤。
- 认领使用存储 CAS/事务保证单一租约；同一步同一执行代次只有一个有效栅栏。认领响应丢失可按稳定幂等键查询同一租约，不生成第二份授权。
- 目标验证 PROD 身份/签名、audience、动作白名单与契约版本、目标 env、规范化参数哈希、计划哈希、期限及本机环境。运行时 DB 身份仍按本环境验证。签名有效也不能越过本机安全边界。
- 在目标持久化唯一键 `(approval_id, step_id, generation)` 的执行记录，再做副作用；同一键不同哈希是篡改，拒绝并回报。开始前复核目标版本、授权未撤销、租约有效。版本已变时停在冲突，不静默更新参数。
- 本地可事务化的动作将副作用、执行记录、outbox 回执放同一事务。外部副作用使用同一稳定幂等键；不能可靠去重/读回的动作，在远程白名单之外或按“未知，需核对”处理。不能宣称跨系统 exactly-once。
- 目标本地落盘结果及证据摘要，回报 PROD 时带执行身份、相同 ID/哈希/栅栏、起止时间、结果、变更前后版本、目标事件引用。回报仅能更新自己认领的步骤，不能传 `approved=true`、改参数或完成其他环境的步骤。
- PROD 验证回报并以幂等方式收据；目标收到中央收据才标记已回传。重复同结果是重放确认；同一键不同结果进入冲突审计，不能覆盖首次结果。
- Owner 在 `ops.bifrost.lan` 看审批、当前执行位置、失败原因和证据；手机通知仍由 PROD 汇总，目标不另发一张等人审批的卡。成功保持既有安静策略，失败/未知按现有提醒策略送达。

## 5. 失败、重放与部分完成

| 情况 | 必须行为 |
|---|---|
| 未认领前超期 / 被撤销 | PROD 不发租约，目标也验证期限；不会自动重建待批单 |
| 已认领未开始时过期 / 失联 | 不开始副作用；报 not-started / expired，回报恢复后补传 |
| 执行中断网、进程崩溃、租约失效 | 标 running/unknown 并冻结依赖步骤；旧执行者不得继续新步骤，新执行者先查目标账本及副作用，不能因租约过期重跑 D 级动作 |
| 目标已提交、PROD 未收到结果 | 重传持久化回执，禁止重做副作用；目标账本可证实时恢复结果，不可证实时保持 unknown |
| 请求/回报重放、跨环境凭证、哈希/签名/契约不符 | 拒绝并审计；既不创建当地审批，也不放宽身份重试 |
| 目标当前版本不符 | 标 failed/conflict，显示批准时与当前版本；新参数需新决定 |
| 一组动作部分完成 | 保留每步结果与依赖图；停止依赖失败步骤的后续动作。默认也停止未开始的独立步骤，只有批准计划明确允许继续才继续；已完成的不能显示成回滚 |
| 补救 / 重试 | 已批准、范围明确且仍在期限内的幂等步骤可按策略重试；扩大范围、改变哈希或新增补救需 PROD 新单。补救也留独立 step ID 和结果 |

时间使用 UTC，容许的时钟偏差要有界；目标时钟不可验证或超差时拒绝开始。审批有效期、认领租约和执行截止时间是三件事，续心跳不能无限延长批准的执行期限。撤销只能阻止尚未开始的步骤；已经开始的外部副作用不能假称已被撤回。

## 6. 凭证与网络方向

- A 的网络方向是目标 → PROD：领单、心跳、回报、查询收据。使用认证 TLS（或已批准的等效受认证通道）；签名封套仍须验证，以免代理/日志混淆数据。HTTP 明文 bearer 不能成为生产协议。
- 每个环境独立执行身份，绑定 env 和允许动作；能力仅有“领自己的单、续自己的租约、报自己的结果”。不能建人工单、批准/拒绝、读其他环境参数或接管他人的执行。
- **STG 不放 PROD admin token**。PROD 中央签名私钥只在中央；目标仅持验证公钥与自己的受限客户端凭证。PROD 不放 STG runtime DB 写凭证，目标只用本地 DB 身份。
- 单独轮换执行身份、验证密钥与 key ID；吊销后停止新认领，正在执行的保留账本并进入核对，不能悄悄改用管理员身份。凭证下发、RBAC/NetworkPolicy 由单独实施/部署审批覆盖。
- 若选 B，方向改为 PROD → 目标受限接收器，PROD 持 env 限定派发身份；不是把中央 admin token 发给目标。目标回报仍按自身身份认证。
