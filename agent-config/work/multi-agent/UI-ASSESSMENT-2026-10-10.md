# Ops Console 现状评估：瘦身之后，要不要为多 Agent 架构调整（讨论稿）

- **状态**：讨论稿，2026-10-10，多 Agent 协作线程写。结论和建议都要等 Owner 定，未落地。
- **依据**：platform origin/main efeaf69 的 Console 代码盘点，加上 PROD Console 六个页面的只读走查（④ Maintenance 里有审批，按规定没有用浏览器打开）。
- **对照**：ADR §1（Owner 只做三件事）、§6（7 个问题）、§12.2（可见性、粘合剂）、设计 v4。

## 1. 结论

**外壳不用重构，内容要按新架构重写。**

- 7 个问题的外壳是好的：导航只有一层，新增一页只要改 3 处，而且有类型检查兜底。
- 问题出在页面里面。现在每一页都是把瘦身前的旧页面竖着叠在一起（代码约 11.1 万行，7 个外壳页由 19 个旧页面拼成）。
- 和新架构关系最大的两页，④ 和 ⑦，恰恰最弱。
- 新架构需要的几样东西，Console 里一样都没有：
  - 「需要你」的计数；
  - 等待时长；
  - 决策卡；
  - 工作项视图；
  - 规则集；
  - 岗位。

## 2.5 Owner 10-10 的补充：「现在要我做的」和「历史」要分开

Owner 的感受：Ops Platform 的重心已经从后台 CI/CD 变成监控、审批和 Owner 的三件事，所以 UI 应该把「人现在要做的事」放到最重要的位置。现在的页面把它和历史混在一起。比如 Maintenance › Approvals，待批的单子和几十张已经关闭的单子列在同一页。

实测确实如此，而且不只是审批页：

| 页 | 混在一起的东西 |
|---|---|
| ④ Approvals | 同一页里依次是：Open request、Pending、Closed（最新 50 张） |
| ⑤ Releases | 在途的 run 和失败的 run 放在同一张表；10-03 的失败到今天还挂着，没有「已处理」这个状态 |
| ⑦ Progress | 71 条分支放在一张表里：未落地 12 条、遗留 19 条、已合并 40 条 |
| ① Status | 正在响的告警、已退场的信号、几个月前就已关闭的网络升级记录（「CLOSED 2026-07-22」）都在同一页 |

由此定一条贯穿所有页面的版式原则。**每一页都按时间分三段，默认只展开前两段**：

1. **需要你**：要 Owner 现在决定、批准、签收的事。带等待时长。**没有的时候明确写「现在没有需要你做的事」**，这一段空着才是正常状态。
2. **进行中**：系统自己在做的事，Owner 不用管，想看的时候能看到。
3. **历史**：已经结束的。默认收起，或者放进单独的「记录」页；能查，但不占首屏，也不计入任何计数。

另外两条：

- **「需要你」是首页。** 打开 Console 第一眼看到的就是它，再加一句系统结论。导航顺序相应调整，「需要你」排第一。
- **计数只算「需要你」。** 外壳上的数字、手机推送的条数，都只统计第 1 段。

## 3. 建议

**不重构外壳；按「问题」逐页重写内容，每页遵守「结论 → 内容 → 动作」。优先级 ④ > ⑦ > ① > ⑤。**

| 做什么 | 排在哪 |
|---|---|
| **④ 改成「需要你」，并且作为首页**：三类（待你定、待你批、待你签），标等待时长与黄红阈值，短编号，参数可读；已关闭的单子移到「记录」；外壳加「需要你 N」的计数；页签进地址，让通知能直达 | 第 0 步（并入 S0-0 审批体验与 S0-7 D1 过渡层） |
| **各页按「需要你 / 进行中 / 历史」三段重排**（2.5 节）：⑤ 失败的 run 加「已处理」；⑦ 已合并和遗留的分支收进历史；① 去掉已关闭的旧记录 | 第 0 步先做 ④ 和 ⑤；⑦、① 随各自的重写 |
| **页头的结论说真话**：和 ① 的结论同源；① 收成一句结论加红项，去掉已退场的信号 | 第 0 步（小改），完整重写放到运行时第 1 阶段 |
| **⑦ 改成项目进度**：W-n 与 mission 放首屏，分支血缘下钻 | 第 0 步先接 D1 的数据；运行时第 0 阶段换成 mission 和任务 |
| **⑤ 补上**：窗口与队列、策略状态与到期、失败 run 的「已处理」、审计覆盖率、自动回滚记录 | 随发布队列这条并行轨道 |
| **新增第 8 页「团队与规则」**：岗位与候选、参谋长入口（简报加固定的对话入口）、规则集（到期、历史、待签）、额度与可替换性 | 运行时第 1–2 阶段；ADR §6 的「7 个问题」要改成 8 个 |
| **第二轮清理（代码与内容）**：Agent 遗留的按钮和卡片、死代码、过期的 catalog、① 的旧隐喻词汇；修 `BackupStatusPanel` 的 bug | 一条独立的道，第 0 步期间可以和别的道并行 |

**要不要走 Claude Design**：④ 和第 8 页属于新的页面定位，按现有流程应该让 Ops 的设计会话出稿。建议这样排：

- 同时给 Design 一份 ASK，请它出 ④「需要你」和第 8 页的设计稿；
- 设计稿回来再对齐。
