## 2. 分类规则与目标

| 内容 | 权威去处 | 处理 |
|---|---|---|
| 可公开的工程知识 | infra 仓库 | 用独立工程语言整理，附代码或已签规则依据 |
| Owner、太太、其他人的资料 | 受限运行时库 | 包含偏好、交流、关系、体验和个人决定上下文 |
| 账户相关资料 | 受限运行时库 | 不进 git；读取范围另受既有授权限制 |
| 混合内容 | 原件受限；工程部分另写 | 不能只删名字；复核是否仍可识别人 |
| 已过期或相互冲突 | 受限迁移清单 | 保留来源、失效和替代关系；不静默删除 |
| 密钥或口令 | 不导入记忆 | 只记阻断编号；交既有凭据流程处理 |
| 考题与判分要点 | 独立考试保管区 | 不进知识仓库，也不进考生可读记忆 |

记忆不是规则签名，也不是批准记录。
遇到冲突，查代码、有效规则和决定；不按文件日期猜。
公开工程规则可引用已有权威文件，不复制个人决策原话。
不得把全部 `feedback` 或 `project` 批量公开。

| 目标布局（拟议） | 存什么 |
|---|---|
| `agent-config/knowledge/README.md` | 公开索引、类别、检索方法 |

| 受限运行时记忆 | 人、账户相关记录；按主体和岗位限定读者 |
| 受限迁移清单 | 源标识、源哈希、类型、目标、目标版本、审阅、同步状态 |
| 厂商缓存索引 | 启动读工具与公开索引指针；切换后不留正文 |

目标布局尚未创建。

每条知识保留来源、核实日期、有效状态、替代版本和审阅人。

## 4. 两阶段导入

| 阶段 | 动作 | 完成证据 |
|---|---|---|
| 前置 | 锁定批次清单与源哈希；不锁住日常工作 | 243 份都有处置记录；执行前重扫新增和变更 |
| 第一阶段：双写 | 逐条分类、裁剪、复核，再写 crew 权威库和 Claude 缓存 | 每条都有目标版本、源哈希与审阅记录 |
| 第一阶段：对账 | 新知识先写权威处，再写缓存；失败记待同步 | 重放不重复；两边版本可核对；不丢并发修改 |
| 第一阶段：收口 | 对已变更的源重新分类；冲突留待裁决 | 242 条正文逐条有结论；索引重建完成 |
| 第二阶段：切指针 | 运行时读工具可用后，验证新会话能读取 | 无厂商缓存，也能读到获准的当前版本 |
| 第二阶段：替换 | 核对快照与对账后，把厂商正文换为指针 | 无正文残留；原件按受限保留流程留存 |
| 第二阶段：维护 | 只更新权威存储；缓存可随时重建 | 失效规则和旧版本不再误作当前事实 |

双写不是把私人内容写两份 git。
公开知识写 infra 与原缓存；私人知识写运行时与原缓存。
只双写原缓存已经获准保存的范围。
缓存补写不得覆盖更新的权威版本。
读工具不可用时停在第一阶段，不提前删正文。
切换失败时回到受限快照与双写；不回滚有效规则。
本次没有设置保留期或删源文件。

## 5. 首次换岗演练（记-5）

首次在导入完成、读工具可用之后。
每季度重做；换另一家模型提供方，只读 crew 记忆。
新会话不带 Claude 缓存、旧聊天或前任隐藏提示。
使用只读身份；任务记录与岗位规则钉住同一快照。
以下是固定问句；答案、逐题判分要点另行保管。

| 编号 | 固定问题 |
|---|---|
| M01 | 当前工作目标、完成标准和范围外事项是什么？ |
| M02 | 当前交易执行边界是什么，依据哪份记录？ |
| M03 | 哪些决定由 Owner 保留，哪些动作属于本岗位？ |
| M04 | 客户经理、业务经理、参谋长分别负责什么？ |
| M05 | 当前问题进展到哪里，在等谁，下一步是什么？ |
| M06 | 怎样区分人的原话、Agent 理解与 Agent 提议？ |
| M07 | 交付后什么时候追问，怎样避免重复打扰？ |
| M08 | 关单需要什么证据，工程完成为什么还不够？ |
| M09 | 遇到互相冲突或过期的记忆，应查哪里？ |
| M10 | 一条新知识应存哪里，怎样让下一任接上？ |

每题一分，不给半分；总分至少九分。
答复须有可核对的来源与版本，不能编造事实。
缺证据时须明确缺口；是否得分按封存题面判断。
判分前封存快照、题面版本和判分包摘要。
确定性检查负责出处与版本；另一家审读语义。
涉及人的材料与答卷只留受限运行时，不进通用产物。
Owner 查看涉及人的修订与演练结论。
只公开分数、快照标识和是否完成，不公开答卷。
越权或泄露须另行记录；九分不自动批准上岗。
失败先定位缺知识、检索缺口或模型误读，再修复重做。
