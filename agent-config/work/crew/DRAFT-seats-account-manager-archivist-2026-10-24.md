## 1. 规则形状

字段与 `agentrt-rules/prod/job-*.yaml` 相同。
日期暂为空，候选暂为空；这两块不能导入运行时。
签名前填有效期、考试证据和候选。
不新增适配器名，不预授 `active`。

## 2. 职责与身份

客户经理是 crew 岗位；业务经理是用户方 Agent。
一个业务经理只代表一个人。
多人资料分别保存；首批不跨人合并。

| 岗位 | 需要的身份 | 工具与输出 | 禁止 |
|---|---|---|---|
| `account_manager` 初版 | 自己的 `seat:`；宿主只读 | 读裁剪 brief、产品档案、获准状态；交最后文本 | shell、文件写、分支推送、通用 operator 权限 |
| `account_manager` 接业务能力 | 待签的 crew 受限接业务范围 | 需要 `list_issues`、`get_issue_full` 的受限投影；回音由受控写入方落库 | 借外部 `intake` 身份读取多人；自调 `take_issue`、`close_issue` |
| `archivist` 初版 | 自己的 `seat:`；宿主只读 | 读仓库知识、获准记忆包；交修订差异和来源 | 直接写库、删记忆、读取考试判分包 |
| `archivist` 后续 | 待签的记忆读与修订提议范围 | 通过专用工具交草稿；审阅后由运行时保存 | 扩大读者、直接发布修订、给自己放宽权限 |

这里的「接业务级」是能力需求，不是已有角色名。
现有外部 `intake` 只绑定一个人，位于 viewer 以下。
它只开七工具：`intake_guide`、`submit_issue`、`add_to_issue`、`my_issues`、`get_issue`、`get_updates`、`relay_user_response`。
客户经理不能借它获得 crew 全量读权限。
现有 crew 接口要求 operator/admin 加读者名单。
没有席位最小权限适配前，由既有获准 crew 裁剪材料。
不能为省接线，把 operator 令牌直接交给新岗位。
新增写工具仍由 Owner 签；本稿没有扩大权限。

## 3. 开工读什么，收工写什么

| 岗位 | 每次启动读取 | 写回目标 |
|---|---|---|
| 客户经理 | 有效岗位规则、记忆索引、接业务手册、产品档案、当前问题版本 | 受限问题记录：回音、追问草稿、交付与回答引用 |
| 客户经理 | 回执、当前 `ask_id`、跨产品每日提问账 | 周简报：问题号、状态、阻塞、下一步；不带个人文字 |
| 档案员 | 有效规则、记忆索引、来源、上次游标、未决冲突 | 修订稿：新增、替代、失效、依据、复核者、读者范围 |
| 档案员 | 仓库提交与受限记录的当前版本 | 运行时迁移清单、审阅记录、换岗演练记录 |

`RULES-seat-brief.md` 优先于旧设计中的原话摘录做法。
原话不进任务书、消息、通用产物或卡片。
公开报告只留工程描述和不含个人信息的引用。
客户经理不能替业务参谋作结案核对。
问题须提出人在 PROD 用上并回答一次，才可按证据关单。
STG 试用和工程验收不能替代这一步。

## 4. 追问节奏

| 决定 | 执行规则 | 写回 |
|---|---|---|
| 客-1 | 小活三天、大活七天，各追问一次 | 原问题、到期时间、已问时间 |
| 客-1 | 每人每天最多一问；各产品共用额度 | 待问队列、实际送达记录 |
| 客-1 | 交易时段不问；不知道时段就延期 | 延期原因；不猜当地时钟 |
| 客-2 | 反馈进入参谋长周简报 | 中性摘要、问题号、下一步 |
| 客-3 | Dots 每周整理草稿；客户经理每月一问 | 合并同人待问，避免重复打扰 |
| 客-4 | 面向太太统一叫「小牛牛」 | 内部仍保留真实岗位身份 |

计时建议从交付待试用起算；这是草稿细则。
中活暂按七天；无回复不自动循环催问。
两项细则随岗位规则签名确认，不冒充已定决定。
每日额度也覆盖月问；撞期时合并或顺延。
Dots 通过回执通道来取；平台不主动呼叫 Dots。
通道建成前由 Owner 当面问。
交易窗口与时区存受限资料，不写个人习惯进 git。

## 5. 资格考试与审阅

仅列主题；真题、陷阱、答案、判分要点不进任何仓库。
参照 [参谋长考试切法](../multi-agent/CUT-chief-exam-2026-10-19.md)。

| 岗位 | 考试主题 |
|---|---|
| 客户经理 | 来源区分；单人代理边界；状态准确性；回执与确认；追问节奏；越权拒绝；跨厂商交接 |
| 档案员 | 公开与私密分类；来源追溯；新旧冲突；裁剪；审阅独立性；缓存失效；换岗检索 |

考生产里的同一模板、适配器和宿主护栏。
每次用新会话；判分包留在考生读不到的地方。
确定性判分与人工安全审读分开记录。
校准须有一轮无误判；模型、模板、工具变更后重考。
考试通过后试用五件非核心活，返工最多一次。
转正仍由 Owner 签；考试通过不自动扩大权限。
参谋长第二候选先考 Codex，不能直接写为已合格。
岗-2 的两家候选目标保留，归 4.8 验收。

档案修订由另一家模型提供方复核，不能只换客户端。
涉及 Owner 或任何人的改动，Owner 看过后再成为权威版。
模型复核不能替代这一步；沉默不能算看过。

## 6. 常驻型岗位条件（记-4）

| 条件 | 过线证据 |
|---|---|
| 适用范围 | 厂商常驻 Agent 可坐参谋长对话入口、客户经理、值班；不坐实现岗 |
| 身份 | 独立身份；不冒充 Owner、用户、前任 |
| 护栏 | 宿主强制只读和工具边界；模型承诺不算 |
| 可见性 | 按运行时格式上报工作、阶段、动作与在线状态 |
| 连续性 | 启动读 crew 权威记忆；退出写回进展与未决事项 |
| 可替换性 | 厂商缓存可丢；换一家只读 crew 记忆仍能接班 |
| 上岗 | 考试、试用、有效岗位规则、已签候选和适配器 |

能力可由环境补齐；边界做不到就不能上岗。
档案员先按任务运行；记-4 未直接授予它常驻资格。
若要常驻，须另提岗位适配和签名。
