**现行方法**（方案第二节有全部条件和代码位置）：

- **股票池**：
  - SEPA 评估的起点是 `dim_universe`：在市、美元计价的美股普通股。
  - 进入 SEPA 排名还要再满足两条，否则页面显示「Not rated by SEPA」（不是「不通过」）：
    - 至少有 252 根日线（`mart_sepa_technical_eval.sql:18`；综合分是内连接）；
    - 基本面数据足够，即有去年同季的 EPS 作比较基数（`fund_insufficient` 为假，`mart_sepa_screening_ranked.sql:18`）。
  - 10-21 实测排名里有 3,793 只（`screener-wide` 的条数）；`dim_universe` 本身更多，具体多少没测。
  - 期权股票池分 resident / core / edge 三档（10-21 实测 751 只）。Radar、多面筛选用期权池，SEPA 用评估池，两个池差约五倍。
- **规则**：趋势模板 11 条；基本面 8 条；动量 10 个信号；结构 8 个信号；情绪 6 个信号；期权结构分。
- **综合分** = 基本面通过数/8 × 0.30 + 趋势通过数/11 × 0.35 + 动量分 × 0.20 + 期权结构分 × 0.15（没有动量分按 0，没有期权分按 0.5）。**结构 8 个信号和情绪 6 个信号都不进综合分**；API 里叫 `structure_score` 的是期权结构分。
- **分档**（都按综合分和趋势通过数）：
  - 等级：A+ ≥ 0.85、A ≥ 0.75、B ≥ 0.60、C ≥ 0.45、其余 D。
  - 阶段：STAGE_2A（趋势 ≥ 8 且综合分 ≥ 0.70）、STAGE_2B（趋势 ≥ 6）、STAGE_1（综合分 ≥ 0.55）、其余 STAGE_4。
  - 路径：PIVOT（综合分 ≥ 0.75 且趋势 ≥ 8）、SETUP（≥ 0.60）、WATCH（≥ 0.45）、其余 AVOID。
- **缺值**：进了排名的名字，SEPA 每一条缺值都按「不通过」算；上面两类没进排名的名字单列为「Not rated」。
- **页面上三个模型的线**：SEPA 是 SETUP 或 PIVOT；Radar 是 A+ 或 A；Premium 是综合 ≥ 70（neutral）。
- **页面默认值**（S1 把它们算作方法）：默认模型 SEPA；默认股票池 All evaluated；默认空 screen（不带预设）；SEPA 默认权重是服务器那一组（趋势 35、基本面 30、动量 20、期权 15）；Premium 默认权重也是服务器那一组。
- **更新**：周一至周五纽约时间 22:30 跑一次（`30 22 * * 1-5`），只写当天，不补跑；读接口取最新日期，不说是否过期。

## 三、能做的、做不到的

**能做**：选股票池；从 2 个可用预设或已存 screen 起步；在 9 个阶段里开关条件；按 SEPA / Radar / Premium 排序并在页面上调权重（只影响自己的显示）；Why 抽屉看每只的去留依据；存 screen；加进 Candidate Pool；Plan this（建策略计划）；Leaders 看跨日排行；方法面看模型、旧版条件、已存 screen、每晚 SEPA 候选。

**做不到**：看历史某天的结果；导出；在页面上改名、改定义、删除已存 screen（Research API 能改、能退役，页面上没有入口）；保存版本树；页面头上看数据日期。另 3 个预设因为缺数据不提供。

## 四、数据范围

- Research 只读 `raw_market.*`，写 `dw_stock.*`、`features.*`、`research.*`、`journal.*`（另有 `ops_dbt`、`ops_dagster` 运维库）；前端经 Research API 读，不碰 Golden Source 的库。方案调查时没有发现越过 D13 的写入。
- **只有一个 Research 实例**：STG、PROD 页面背后是同一个 `research-api` 和同一个库。在 STG 存的 screen、加的候选，和 PROD 是同一张表；Research 的改动一发就是所有环境。

**复核独立性照原规则**（S6 A）：参谋长席位同时兼业务参谋和总参谋长，它提议或交付的东西不由它自己复核。

**什么算「改选股方法」、要 Owner 定（S1 A）**：服务器端的条件和阈值；综合分四个权重；等级、阶段、路径的分档；缺值当不通过的做法；**股票池的定义，包括第二节那两条排除**；窗口（252 日、多面筛选的 7 天）；页面默认值（第二节列的那几项）；新增排名或推荐逻辑；把「未知」改成「通过」。
**不算**：太太为自己调视图；如实显示未知、依据和日期；修复规则和实现之间明确的偏差；同语义、同结果的性能优化。
**注意**：第二节写明的排除和默认值是现行方法本身，不是「偏差」。拿不准是不是偏差的，按改方法处理、先问 Owner。

**投入（S7 A）**：沿用已签的 `standing-envelope:dev` v4，不另定数：dev 租户，最高到推分支（`max_action: branch`），每 mission 40 次尝试或 48 小时，执行者 claude / codex / cursor / deterministic。同一问题跨 mission 的累计先在问题记录里手记（第九节）；费用和订阅一律另报 Owner。墙钟预算等待试用时也在走，超时由 Owner 在卡上加时。

**数据可见范围（S8 A）**：业务参谋和 Agent 只读 Screening 的结果和方法数据（`dw_stock`、`features`、`research` 的读接口和已存 screen）；不读账户内容；不向外部 AI 发数据（第 3 步再定）。

**已存 screen（S9 A）**：维持共享。家里两人互相能看、能改；将来要分开再改表。
