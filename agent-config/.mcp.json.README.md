## 令牌分级（这是桥的真正价值所在）

`platformClient.ts` 读 `PLATFORM_OPERATOR_TOKEN` 作为 Bearer。三个只读桥在该变量里放的是
**viewer 令牌**（`${PLATFORM_VIEWER_TOKEN:-platform-viewer-dev}`），因此：

```
Bearer platform-viewer-dev    → GET /api/v1/auth/capabilities → role: "viewer"
Bearer platform-operator-dev  → GET /api/v1/auth/capabilities → role: "operator"
```

只读桥即使被要求调用写路由，也会被 **platform-api 服务端 RBAC 拒绝** —— 机械强制，
不依赖 Agent 自律（与 `AGENT_FACTS.md` §8、双飞轮 Vision 的边界原则一致）。

令牌来自 `bifrost-platform/config/platform-auth.yaml`（viewer / operator / admin / trade-satellite）。
`${VAR:-default}` 形式：设了环境变量就用真令牌，未设则回落到 dev 默认值 —— **令牌不落盘**。
（Cursor 侧 `~/.cursor/mcp.json` 是明文写死 operator 令牌。）

## focus 桥的实现

**此前 focus 桥是空壳**：`index.ts` 只对 `prometheus` 分支做了实现，传
`kubernetes` / `redis` / `postgres` 会落到 `else` 分支注册全量 85 个工具 —— 三份完全重复。

现已在 `mcp/platform/src/focusBridges.ts` 补上真正实现：

- 按领域定义工具白名单，依据是 `api/internal/mcp/catalog.go` 的权威目录（route + level + role）
- `index.ts` 的 `reg()` 包装器按白名单过滤注册；focus 为空 → 注册全量（**无回归**）
- 未知 focus 值走全量而非报错，向后兼容既有配置

分域原则：

| focus | 收录 | 刻意排除 |
|-------|------|---------|
| `kubernetes` | cluster summary/nodes、namespaces ensure、workload rollout/scale/delete-pod、node cordon/uncordon/drain/wake/poweroff/join、addons ensure | PG / 数据层路由（归 postgres） |
| `redis` | matrix、verify_payload、verify_mission_snapshot、cluster summary | 无 —— platform-api 没有 Redis 专用端点，这是刻意很薄的切片 |
| `postgres` | matrix、verify_payload、data-freshness、backup-status、data-clone status | 写操作：`trigger_cnpg_backup`、`repair_cnpg_wal_store`、`trigger_data_clone` |

需要被排除的写工具时，用主 `bifrost-platform` server。
