## 1. 管哪块（坏了叫它）
- **条目格式和总目录**：一样东西在图上长什么样；系统里有哪几类东西、每类唯一出处是哪张表。
- **归属表日常维护**（11-20 从解耦线接，清单 `map/handover-from-decouple-2026-11-20.md`）：`bifrost-platform/config/domain-ownership.json`、前端清点 `console/scripts/frontend-domain-map.mjs`、模块清单第一版、给指标线的运行时键（`<namespace>/<workload>`、`node/<名字>`、`host/<名字>`）、合约栏没登记的共用表的登记。例外（主统筹 11-20 裁）：解耦线搬代码时在同一个提交里改被搬的那几行，事后通知本线。
- **持续扫描和无法感知池（常设职责，决定 2026-11-20）**：不是一次性盘点，是机器一直在扫系统里有什么不在图上（现在：platform workers 每 10 分钟扫 main，`api/internal/catalog`）。扫到的**不自动进图**，一律进「无法感知」池（账本）：系统看不见它，不等于它没有，按缺陷登记，每条带发现时间，逐条评审：认领进图｜删（删前另量有没有人用，有数据的删改归 Owner）｜量不出标「不知道」（结论在 platform `config/catalog-review.json`）。池子里有不干净的条目是正常的：目标不是清零，而是每条都有人看过、有结论、有发现时间，最老一条的天数只降。扫描和池子都是机器产的读数，不手填。读口 `GET /api/v1/catalog/unperceived`、MCP `get_unperceived`；措辞用「无法感知」。
- **台账**：共享笔记 `map/state.md`。
- **生命周期跟踪**：`releasefreeze`（没人用，在信任锚内）等要退役的东西；删不删由 Owner 定，默认保留。
- **`mixed` 欠账**：只量不判，只减不增（主统筹 11-20 裁，不给装配根单算一类）。
- **状态一栏拼装**（段4）：活着、口子通、边界干净、图是新的，只由机器算。
- **读口**：「X 归谁」「领域 Y 有什么、开放什么、健康吗」「图外有什么」，接口加 MCP 工具。
- 一句话：户籍，不是法院，不是施工队。
- 不管：各领域那一栏的内容（各领域填）；增减合并领域（Owner）；越界判不判、过线值（裁判规则，CI 线日常运转，改它交 Owner，LAW-9）；越界引用整改、`mixed` 包拆分（解耦线）；节点和老家表（算力线，指过去）；分数怎么算（评估线）；成熟度尺子（Owner 说先不定）。

## 2. 对外的口子（LAW-10，五种形式）
| 形式 | 内容 |
|---|---|
| 接口（读） | `GET /api/v1/catalog/unperceived`（图外清单）、`/catalog/owner`（X 归谁，`repo=cluster` 查工作负载）、`/catalog/index`（总目录）、`/catalog/status`（每个领域四个灯）、`/catalog/domain`（一个领域名下的东西、合约和灯）。都只读 workers 存下的结果 |
| MCP 工具 | `get_unperceived`、`get_owner`、`get_catalog_index`、`get_domain_status`、`get_domain` |
| 页面 | 不新开：四个灯在 Ops 的 Status 页「Domains」一块 |
| 事件 | 没有（11-20 判不做：量不到订阅方；有了再加「图变了」） |
| 指令 | 没有；改图走合入 |
| 别人可读的存储 | 仓库里那几份登记表本身 |
- 保证：每条可追到出处（文件和行，或集群对象）；状态无手填；读口不在请求时列集群（事故 #63）。
- 不保证：线上服务不许依赖它；它挂了页面看不到图，系统照跑。
- 现在读归属表的（改格式要带着）：codeguard、domainscore、cidomains、ciconfig、bus/registry、storekit、actor 契约测试、server 三个测试、`bifrost.units.yaml`、console 脚本与 CI 页【量，约 27 个文件】。
