## 1. 管哪块（坏了叫它）
- **条目格式和总目录**：一样东西在图上长什么样；系统里有哪几类东西、每类唯一出处是哪张表。
- **归属表日常维护**（11-20 从解耦线接，清单 `map/handover-from-decouple-2026-11-20.md`）：`bifrost-platform/config/domain-ownership.json`、前端清点 `console/scripts/frontend-domain-map.mjs`、模块清单第一版、给指标线的运行时键（`<namespace>/<workload>`、`node/<名字>`、`host/<名字>`）、合约栏没登记的共用表的登记。例外（主统筹 11-20 裁）：解耦线搬代码时在同一个提交里改被搬的那几行，事后通知本线。
- **图外清单（无法感知的东西）**：系统看不见它，不等于它没有（Owner 11-20）。按缺陷登记，每条带发现时间，逐条评审：认领进图｜删（删前另量有没有人用，有数据的删改归 Owner）｜量不出标「不知道」。页面和读口措辞用「无法感知」，显示条数和最老一条天数。
- **生命周期跟踪**：`releasefreeze`（没人用，在信任锚内）等要退役的东西；删不删由 Owner 定，默认保留。
- **`mixed` 欠账**：只量不判，只减不增（主统筹 11-20 裁，不给装配根单算一类）。
- **状态一栏拼装**（段4）：活着、口子通、边界干净、图是新的，只由机器算。
- **读口**：「X 归谁」「领域 Y 有什么、开放什么、健康吗」「图外有什么」，接口加 MCP 工具。
- 一句话：户籍，不是法院，不是施工队。
- 不管：各领域那一栏的内容（各领域填）；增减合并领域（Owner）；越界判不判、过线值（裁判规则，CI 线日常运转，改它交 Owner，法 29）；越界引用整改、`mixed` 包拆分（解耦线）；节点和老家表（算力线，指过去）；分数怎么算（评估线）；成熟度尺子（Owner 说先不定）。

## 2. 对外的口子（法 28，五种形式）
| 形式 | 内容 |
|---|---|
| 接口（读） | 整张图；一个领域的全部；「X 归谁」；图外清单；各类覆盖数（段1 落地后写具体路由） |
| MCP 工具 | 同样三问：谁的、有什么、图外有什么 |
| 事件 | 一个：图变了（哪条、谁改、哪个提交）。图外新东西只进清单，不发事件 |
| 指令 | 没有；改图走合入 |
| 别人可读的存储 | 仓库里那几份登记表本身 |
- 保证：每条可追到出处（文件和行，或集群对象）；状态无手填；读口不在请求时列集群（事故 #63）。
- 不保证：线上服务不许依赖它；它挂了页面看不到图，系统照跑。
- 现在读归属表的（改格式要带着）：codeguard、domainscore、cidomains、ciconfig、bus/registry、storekit、actor 契约测试、server 三个测试、`bifrost.units.yaml`、console 脚本与 CI 页【量，约 27 个文件】。

## 3. 谁用它，它用谁
- 用户：CI 线（领域墙、合约检查、测试归属）、评估读口、简报、Ops、Agent、各领域线（填自己那栏、认领图外）。
- 它用：Prometheus 读数（状态灯）、事件登记表、动作目录、算力线数据、集群读口。

## 4. 权限
- 自己做：加行、改格式、写读口、图外清单、推 `ready/<名字>`、STG 发布（按根 CLAUDE.md §5）。
- 不自己改：「没有行的包默认归底座」这条默认值。主统筹 11-20 裁：改它会动底座领域墙的判定，是改裁判规则（法 29）。本线先把图外清单做成只读读数，不动 codeguard 判定；读数出来后写成提议交主统筹带给 Owner。
- 有数据的删改（图外评审里的删）先量、留导出，走 Owner 的卡。
- 不做：替别的领域写合约；装 Backstage；新开 Ops 页面。
- 硬边界不碰：D10、Secret、PROD 发布、auto mode。
