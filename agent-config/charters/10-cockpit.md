# 10 Cockpit 章程：我们一起建的世界

Owner 2026-11-17、11-18 和主统筹讨论后定的方向，主统筹整理。这一页指导 Ops 游戏化的所有落地。

## 1. 一句话

**Ops 游戏化不是做一个游戏，是把人和 Agent 一起做事这件真事，变成一个人一眼能懂、能动手参与的世界。**

## 2. 为什么做

- 现有 UI 的直观程度，已经满足不了 Owner 对 Ops 的监控和互动。
- Agent 多了以后，瓶颈不再是干得够不够快，而是人看不看得懂、管不管得住。
- 图表要人先学怎么读；建筑、道路、红绿灯、工地是人本来就熟悉的世界观。借这套世界观，理解和互动的门槛都低很多。
- 这个世界由人和 Agent 一起打造：人定它该成为什么样、守什么规矩；Agent 把它建出来、修好、运转起来。建得好不好，走一圈就看得出来。

## 3. 七条原则

1. **表现层和系统分开。** 星云图、2.5D 城市都是同一份真实系统的不同皮肤。画面怎么变，不影响系统怎么做；系统的工作也不等画面。
2. **画面上的一切都对应真事。** 每个动作和状态都对应一件真实发生的事。不为好玩发明系统里没有的动作。
3. **人只做人该做的。** 人在游戏里能点的，就是人真实的职权。不该人管的事，界面上就没有按钮。
4. **Agent 的真实工作要看得见。** Agent 能做什么、正在做什么、被什么拦住，由小人和设施的状态表现。
5. **一个比喻只有一种含义。** 路不能一会儿表示依赖、一会儿表示通信。
6. **世界是分档的。** 地块只有 1×1、2×2 这样的整档，不要 1.5、1.8。所有事物和关系都切成固定档位才能落地。
7. **真实优先于好看。** 数据从源头现算（法 30），读不到就显示 unknown。画得好看但和实际脱节，比没有图更危险。能反映就反映，不能反映不要假装（法 40）：不用默认绿色、示意动画或估算值填补。
8. **目标是看出系统是否顺畅。** 首页先答现在顺不顺、堵在哪。验收用真实事件回放，不看文字也能发现问题。

## 4. 人和 Agent 在世界里的分工

| 人做 | 真实含义 |
|---|---|
| 放蓝图 | 提目标或需求，怎么建由 Agent 定 |
| 在法院敲槌 | 立法、改法、改裁判规则，一次一件，看回报和代价 |
| 按 Trade 火箭的发射钮 | Trade 的生产发布 |
| 确认拆除有数据的建筑 | 有数据的删改 |
| 在保险库盖章、用钥匙 | 签名规则、口令和 Secret |
| 走到围栏前放行 | 只有人能做的手续，例如 auto mode 拦下后亲口放行 |
| 拖楼、修路 | 整理自己的地图，不影响系统，不产生需求 |

| Agent 做 | 真实含义 |
|---|---|
| 搭脚手架、盖楼 | 领活、写代码 |
| 送进总装厂房质检 | 跑 CI |
| 履带车运火箭、自动升空 | 规则覆盖的 Platform 发布 |
| 卡车把建材直接运进地基 | 只增不删的迁移按标准直跑 |
| 信使送信 | 总线事件和回执 |
| 补墙、修路 | 修缺陷、还技术债 |
| 拆旧路、通新路 | 退役旧通道、接上新链路 |
| 走到围栏前举牌 | 被规则或权限拦下，等人或换路 |

人点不了的同样重要：Platform 火箭没有人的发射钮，楼坏了人不能亲手修，Trade 实盘发射台封着（D10），游戏里没有任何解封或下单入口。

## 5. 世界观词典

词典写在代码里，机器可读，页面的「?」能看。每一项写清：**比喻、真实含义、档位和阈值、数据来源、人能不能操作**。新东西进世界前先答两问：**它在世界里是什么，有哪几档。** 答不出就先不加。

初版（实现时可调整，调整后比喻仍然只有一种含义）：

| 世界里 | 真实的事 | 档位 |
|---|---|---|
| 地块、建筑大小 | 模块的分量 | 1、2、4、8 |
| 楼的健康 | 领域的状态，技术债按领域汇总 | 完好 / 有裂缝 / 漏水 / 危楼 |
| 工程 | 需求和功能 | 蓝图 / 施工 / 验收 / 落成 |
| 工人 | 席位和 Agent | 干活 / 等待 / 被拦 / 空闲 |
| 路况 | 流量和排队 | 畅通 / 缓行 / 拥堵 / 断路 |
| 路的等级 | 链路的重要程度 | 小路 / 街道 / 主干道 |
| 红绿灯 | 一道机器检查 | 绿 / 黄 / 红 |
| 法规 | 法落地的强度 | 路牌（只有文字）/ 红绿灯（机器检查）/ 路障（硬拦） |
| 踩出来的小路 | 绕行账，规矩不顺的证据 | 浅 / 明显 / 深 |
| 火情 | 事故 | 冒烟 / 着火 / 停摆 |
| 电站负荷 | 算力 | 正常 / 紧张 / 过载 / 停电 |

分档的规矩：

- 档位少而固定，状态类不超过 4 档。
- 档位由真实数据按固定阈值算出，阈值写在代码里并带版本，不手工给单个对象定档。
- 原始数不丢，走近或点开才看到。
- 靠近阈值要防抖，不能来回跳。
- 大量明细先汇总：200 多条技术债不画成满城裂缝，整栋楼一个状态，走进去才看具体哪几条。

## 6. 落地路线

一步验收通过再走下一步。

| 步 | 做什么 | 验收 |
|---|---|---|
| 1 建造页 | 地皮、道路、楼、绑定、保存 | 已在看图台走通 |
| 2 上真 Ops | 独立页面，不替换首页；只读给能看 Console 的人，编辑和保存只给 Owner | Owner 能用自己的手机打开、缩放、拖放、保存 |
| 3 三样真实状态 | 发射台、总装厂房排队、举牌的工人 | Owner 看一眼能答出：现在在发什么、堵在哪、有没有事等他 |
| 4 铺开词典 | 楼的健康、技术债、工人、总线路况、事故、算力 | 每个画面元素都能点开看到来源；读不到的显示 unknown |
| 5 人的动作接通 | 法院、放行、Trade 发射钮等，都接到现有的正门 | 游戏不新增权限，批准仍落在平台现有的审批和记录上 |
| 6 建造即需求 | 放蓝图生成结构化需求进计划领域，工程状态跟真实工作走 | 一张蓝图能走到上线，全程看得见 |
| 7 成为首页 | Owner 认可后替换首页；「透视」可切到星云图 | Owner 问进展的次数、读长消息的时间确实下降 |

总的验收标准只有一个：**有了这个页面，人和 Agent 互动的成本是不是真的低了。**

## 7. 不做什么

- 不做要安装的程序，它是 Ops 里的页游，手机、平板、电脑都能用。
- 不一次生成整座城；先有地，再有路，楼一栋栋放。
- 不让人为了维护这座城花时间。平时扫一眼，没事就走。
- 不用画面代替证据。立法这类决定，游戏把人带到那里，判断仍看文字、数字和回报。
- 不碰交易和钱（D10）。
- 不因为画面需要去改系统行为。缺数据按合约找数据的主人要读口。

## 8. 管哪块

Ops 游戏化的表现层：看图台、城市页面、部件库、布局文档、世界观词典。沟通层神经图（星云图）的外观已定，由沟通线维护。

## 9. 对外的口子

- 接口：`GET/PUT /api/v1/home/layout`（布局，读给能看 Console 的人，写只给 Owner）。
- 事件：`home_layout_saved`，账本流 `home:layout`。
- 存储：布局 JSON 存 artifact，账本记指针，seq 是版本。
- 用别的领域的数据，只走它们的对外读口。

## 10. 权限

- 自己定、自己做：画面、交互、部件、词典、页面结构、前端依赖。
- 走现有规则：进 main、STG、platform PROD 发布，只增不删的迁移。
- 不做：新增审批入口或绕过现有审批；碰信任锚、签名规则、D10；写死数字和状态。

## 11. 目标和读数

- Owner 手机上回答三个问题要几秒：在发什么、堵在哪、有没有事等他。
- 画面元素里有真实数据来源的比例。
- Owner 问进展的次数、需要读的长消息数量（看趋势）。
