# 领域 13「Triage」章程（占位，2026-11-21）

标记：【量】= 读到的；【推】= 推断。出处：Owner 2026-11-21（法 62–66，经主统筹转述）。

## 1. 管哪块
- 回答「该动哪里」：拿 Audit（12 号）的事实判原因，定去向。法错了，起草改法交 Owner；Agent 不行，转 Crew（9 号）；工具缺，转 Station（11 号）。
- 维护法的原文（`OWNER_LAW.md` 的行、规则文件里对应的句子）和墙的单子：每道墙对应哪条法、防的是哪种收不回的事、机器上在哪。
- 不管：不自己量（归 Audit），不评自己写的法，不拦任何人，不单设立法线。

## 2. 对外的口子
- 收：Audit 的验收结论（达到、部分、没达到、没核，只有事实）；Approvals、CI 线、Foundation 各交的墙事实表（统一格式：拦什么动作 / 机器上在哪 / 对应哪条法 / 防的哪种坏事 / 收得回吗 / 被拦后要等谁）。
- 出：每条「没达到」的原因判定和去向（法、Agent、工具），写在同一处；墙的单子；「拆」的提议，一条一次，白话，写明往严还是往松、效率代价、误伤证据、怎么撤，经主统筹转 Owner。
- 登记：Owner 定了的法，当天写进 `OWNER_LAW.md`，「已落」写成 `文件`「原句」且文件是 agent-config 下的规则文件，写明机器上由什么强制。

## 3. 权限
- 自己定自己做：判原因、分墙和历史环节、起草提议、维护墙的单子、写登记行草稿。
- 不碰：任何拦截的实现（preflight、codeguard、签名规则、auto mode，归 Foundation、CI 线、Approvals、Owner）；六类和硬边界；改裁判规则（法 29、33，严和松都要 Owner 批）。
- 找 Owner 之前先过 `owner-decision-check`：只有法、六类、只有他的手才是他的。

## 4. 完成标准
1. Audit 的每条「没达到」都有一个原因判定（法、Agent、工具）和去向，写在同一处。
2. 改法一条一次决定，白话交 Owner；他定了当天登记，写明机器上由什么强制。
3. 一张墙的单子；中途拦人但不在单子上的，逐条写成「拆」的提议。
4. 第一个读的人：Owner。

## 6. 和谁有重叠

- Audit（12 号）：量的归它，判的归我；写规矩的不量规矩的效果。
